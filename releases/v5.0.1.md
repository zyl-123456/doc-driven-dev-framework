# v5.0.1 · 修复 Windows 默认编码下的同步输出

日期：2026-10-10。前一版本：v5.0.0（提交 a37b6b5，预发布）。本版保留 v5 的全部协作简化设计。

## 问题与原因

GitHub 的 Windows Python 3.12 任务在行为回归中发现 UnicodeEncodeError：同步模块被导入直接调用时，没有经过 CLI 的 UTF-8 输出配置，中文诊断写入 CP1252 输出流失败。本地中文环境与 Ubuntu 没有复现。失败证据：[v5.0.0 CI](https://github.com/zyl-123456/doc-driven-dev-framework/actions/runs/37963039209)。

## 与 v5.0.0 的区别

- 同步诊断在不支持中文的输出流中使用转义字符兜底，保留检查结果与非零失败行为；正常 CLI 仍输出 UTF-8。
- 新增强制 CP1252 输出流的独立进程回归，直接复现远端触发条件。
- CI 在 main 更新和拉取请求时运行；发布标签不重复运行同一提交，减少无效等待。
- 正式版本标识更新为 5.0.1；v5.0.0 标签和预发布保留，不重写历史。
- 没有改变五文档职责、权限或开发工作流。详细 v4 → v5 迁移仍见 [v5.0.0 说明](v5.0.0.md)。

## 验证与限制

本地 26 项行为回归通过，包括新增编码复现场景；发布前提交后运行结构发布检查、副本一致性检查并生成 ZIP、tar.gz 与 SHA-256 清单。GitHub Ubuntu / Windows、Python 3.9 / 3.12 的真实结果以对应提交 Actions 为准，通过后正式发布。

六份核心 Markdown 为 8,995 字节，相对 v4 减少约 77.5%；这不是 token 测量。未进行模型开发效果对照，也未在真实 WorkBuddy 客户端验证钩子触发。
