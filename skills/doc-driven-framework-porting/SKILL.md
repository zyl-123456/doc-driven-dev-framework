# 建立或迁移框架 · v5

确认或从上下文提取项目目标、目录与已有授权。已有规范优先，不覆盖现有人类需求。

## 新项目

安装后的 templates 是发布副本；在母版仓库工作时从仓库根取 00–04、START_HERE 和 verify.py。
把五文档放开发驱动文档目录，入口和检查器放项目根。填写目标、约束、验收样例及已有授权，删除不适用的占位项；无需拆解时明确写不需要。入口用相对 Markdown 链接指向实际文档目录。
用 python verify.py --mode project 检查结构。功能测试按项目单独选择，项目尚不能运行时如实说明。按用户任务授权组织版本提交，不为每次交流建提交。

## 已有项目

先读现有规则与当前证据，展示 v4 → v5 差异并在授权内迁移。保留需求、设计理由和原始证据；重复问题与假设合并为一个主要位置，其余引用。不要把模板覆盖到已有内容上。

## 换设备

母版内的 deploy-kit/README-新设备部署.md 提供可选 WorkBuddy 部署方式。
安装只负责技能和钩子适配，不等于客户端生效。其他工具用各自项目指令衔接 START_HERE，不照搬 WorkBuddy 配置。
