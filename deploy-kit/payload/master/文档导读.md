# 五文档导读 · v5

阅读顺序由任务决定，不把五份文件当成必读长提示。

| 文件 | 何时需要 | 不必写什么 |
|---|---|---|
| 00 | 确认授权、协作与项目边界 | 部署历史、产品特有规则的通用化 |
| 01 | 确定目标、约束和验收 | 实现细节、未经确认的新目标 |
| 02 | 一个需求涉及多个技术问题 | 小修改的重复转述、重复疑问或假设表 |
| 03 | 关键设计、环境、测试与重审 | 完整代码解说、已失效方案全文 |
| 04 | 未解决事项、结果与证据 | 每轮聊天、完整测试输出、重复需求 |
| START_HERE | 进入项目与交接 | 全部纪律、详细里程碑历史 |

一个按钮文字修正：读相关需求与代码 → 修改 → 检查 → 必要时更新受影响的一行记录。
一个跨模块功能：确认效果与边界 → 拆技术问题 → 设计重要接口 → 小步实现与验证 → 更新相关内容。
只读讨论：直接回答，不创建技术编号，不要求提交。

每条信息一次定义，其余用引用。明确编号定义支持标题、列表起首，或第一列为“编号 / ID / 标识”的表。普通测试表中的需求编号是引用，不当作新的定义。没有编号也可使用五文档。
