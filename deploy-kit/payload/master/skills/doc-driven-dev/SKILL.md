# 按任务协作 · v5

先看项目入口 START_HERE 的当前状态和相关文档路径；缺入口时直接检查项目既有说明，不自行移植框架。

- 只读取本任务需要的需求、约束、设计和代码；全面审计才全量读取。
- 人类决定需求。已有授权持续有效，格式整理和常规技术选择不重复确认；实质含义改变或超出授权才提问。
- 简单修改直接实现并检查，不要求新增 TECH / D / M。复杂功能明确验收样例和重要接口后小步推进。
- 问题定义在 01，设计与理由在 03，未解决假设、限制和证据在 04；其他位置只引用。
- 实质任务完成、关键决定形成或需要交接时维护受影响的文档和快照；讨论、只读审阅无需落档、测试或提交。
- 核对实现用代码、运行与测试；核对意图用人类需求。不要因实现不同就改需求。
- verify.py 只检查文档结构，报告功能检查与人工验证的独立结果及限制。
- 按任务或发布组织提交，保留他人改动。并行工作约定文件负责人，由主线整合公共文档。
- 规则按实际失败修订，不复制项目特定平台规则，不宣称行数阈值保证模型质量。

框架升级、部署和版本发布是独立任务；不要因普通开发顺带修改用户级配置。
