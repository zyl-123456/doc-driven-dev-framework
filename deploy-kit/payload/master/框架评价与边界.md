# 框架评价与边界 · 2026-10-10

## 当前判断

保留人类意图、重要取舍、未解决事项和证据有价值；固定流程与大量重复上下文可能增加成本。v5 以简化为主，是否提升实际效果需要对照验证。

模型能从代码恢复许多技术信息，但不能可靠恢复人类未写下的偏好和被否决方案的原因。文档应优先保存这些信息。

## 研究与适用边界

- [Evaluating AGENTS.md，2026-09 修订版](https://arxiv.org/html/2602.11988v3)：在所测 Python 编码任务中，上下文文件没有普遍提高任务成功率，平均推理成本增加超过 20%。不能直接外推为长期交接无价值，也不能忽略新增规则的成本。
- [Anthropic 上下文工程](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)：用高价值信息和按需检索管理有限上下文，模型更强时减少细致规定。
- [规格驱动开发工具评估](https://www.martinfowler.com/articles/exploring-gen-ai/sdd-3-tools.html)：小任务套完整流程可能过重，重复 Markdown 增加审阅成本。
- [OpenAI 项目指令文档](https://learn.chatgpt.com/docs/agent-configuration/agents-md)：可用项目指导衔接文档；WorkBuddy 配置不是 Codex 通用入口。

这些资料支持改进方向，不构成本仓库的效果实验。旧文档中“三次交接回本”“成本一次性”“800 行质量红线”“绝不会限制模型”缺少充分依据，v5 不再作为规则采用。旧内容可查 v4.0.0 标签。

## 什么已经被检查

verify.py 检查文档存在、显式定义与引用、可解析的相对 Markdown 链接、快照字段。规模超限只提醒；验收记录计数只读对应章节。

它不检查自然语言需求含义、全部路径提及、链接锚点、外部网页可用性、功能正确、安全合规或快照新鲜度。通过检查不能当作产品交付认证。

## 何时值得使用

长期迭代、频繁换会话、人类取舍较多或需要交接的项目，收益可能较大。一次性脚本通常只需任务说明；已有仓库规范优先，不自动创建另一套治理系统。

## 后续评价方法

用相似的修复、新功能、跨模块调整和隔期接手任务比较完整 v4、精简 v5 与原有说明加按需探索。固定起始代码与模型条件，避免后做方案直接借用前一次答案，记录人类耗时、返工、验收结果、上下文与文档维护成本。结果不足时保留“不确定”，不把文档变短等同于模型效果已提高。
